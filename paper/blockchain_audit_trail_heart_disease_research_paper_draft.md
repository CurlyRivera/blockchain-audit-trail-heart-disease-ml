Designing a Blockchain-Inspired Audit Trail for Machine Learning Models Used in Heart Disease Risk Prediction

Abstract

This project develops a Python-based heart disease risk prediction workflow and pairs it with a blockchain-inspired audit trail designed to improve transparency, reproducibility, and accountability in health AI model development. Version 1 used logistic regression to predict heart disease presence from the UCI Heart Disease dataset and generated an initial tamper-evident audit record. Version 2 expanded the project by comparing logistic regression, random forest, and gradient boosting models; creating a multi-block audit chain; testing tamper-detection scenarios; and adding feature importance analysis to improve interpretability. Version 3 further expanded the project by adding a TensorFlow/Keras neural network model as a deep learning baseline, comparing its performance against traditional machine learning models, organizing reusable Python code into source files, adding reproducibility files, and extending the audit chain to include deep learning-specific model details. The results show that the neural network performed competitively with traditional machine learning models but did not clearly outperform them, highlighting the importance of matching model complexity to dataset size, interpretability needs, and health AI governance requirements. Overall, this project demonstrates how machine learning, deep learning, biomedical data science, and blockchain-inspired recordkeeping can be combined to support more transparent, reproducible, and auditable health AI research workflows.

Introduction

Machine learning models are increasingly used in health-related prediction tasks, but their adoption depends not only on predictive performance, but also on trust, transparency, reproducibility, and accountability. In clinical and biomedical contexts, researchers, clinicians, and health care stakeholders need to understand how a model was trained, what data were used, how the model performed, and whether previous model records have been modified. Without a reliable way to track dataset versions, model versions, evaluation metrics, model settings, and workflow changes, health AI systems may become difficult to reproduce, audit, or trust.
Heart disease risk prediction provides a useful case study for exploring these issues because cardiovascular disease is a major health concern and can be studied using structured clinical variables such as age, cholesterol, blood pressure, chest pain type, maximum heart rate, and other patient-level measurements. These variables make the dataset useful for comparing traditional machine learning models and deep learning models in a controlled research-style workflow.
This project investigates how a blockchain-inspired audit trail can be applied to the development of machine learning and deep learning models for heart disease prediction. The goal is not to build a clinically deployable diagnostic system, but to create a research prototype showing how predictive modeling can be paired with transparent documentation, tamper-evident records, reproducible outputs, and model governance practices. By extending the project through multiple versions, the workflow demonstrates how model history can be tracked as the project evolves from a single logistic regression model to model comparison, feature importance analysis, and a deep learning baseline.

Background

Biomedical informatics combines health science, data science, computer science, and information management to improve the use of data in health-related decision-making and research. Machine learning can support biomedical informatics by identifying patterns in clinical or public health data, but predictive models must be carefully documented and evaluated before they can be trusted. Model performance alone is not enough; the development process also needs to be transparent, reproducible, and auditable.
A blockchain-inspired audit trail is a recordkeeping approach based on concepts commonly associated with blockchain systems, such as hashing, linked records, and tamper-evident history. In this project, the audit trail does not use a full blockchain network or cryptocurrency system. Instead, it applies blockchain-inspired principles to track machine learning model development. Each audit block records information such as the dataset hash, model name, model version, training date, features used, hyperparameters, performance metrics, previous block hash, and current block hash. If an earlier record is changed, the recalculated hash no longer matches the stored hash, making the change detectable.
This approach is relevant to health AI because medical and biomedical prediction workflows require strong documentation. A model used in health-related research should be traceable from dataset preparation through model evaluation. By combining predictive modeling with auditability, this project explores how health AI workflows can become more transparent, reproducible, and accountable.
Deep learning is also relevant to biomedical informatics because neural networks can model complex relationships in data. However, deep learning is not automatically better than traditional machine learning, especially when the dataset is small and structured. Traditional machine learning models such as logistic regression, random forest, and gradient boosting often perform well on tabular clinical datasets because they can learn patterns from smaller sample sizes and may be easier to interpret. For that reason, this project adds a neural network model not to assume that deep learning will outperform traditional models, but to evaluate whether a basic deep learning approach improves performance and to demonstrate how deep learning model details can be included in an audit trail.

Methods

This project used the UCI Heart Disease dataset as the basis for heart disease prediction modeling. The dataset contains clinical variables commonly used in heart disease prediction, including age, sex, chest pain type, resting blood pressure, cholesterol, fasting blood sugar, resting electrocardiographic results, maximum heart rate, exercise-induced angina, ST depression, slope, number of major vessels, thalassemia-related information, and heart disease diagnosis. The original target variable was converted into a binary classification outcome, where 0 represented no heart disease and 1 represented heart disease present.
In Version 1, a logistic regression model was trained using Python. The model was evaluated using accuracy, precision, recall, F1 score, and ROC-AUC. An initial blockchain-inspired audit record was created for the model run. This record included the dataset name, dataset version, dataset hash, model name, model version, training date, features used, performance metrics, previous block hash, and current block hash.
Version 2 expanded the methodology by comparing three traditional machine learning models: logistic regression, random forest, and gradient boosting. Each model was trained using the same cleaned dataset and the same train-test split to allow a fair comparison. The models were evaluated using the same performance metrics: accuracy, precision, recall, F1 score, and ROC-AUC.
Version 2 also expanded the audit trail from a single audit record into a multi-block audit chain. Block 1 recorded the logistic regression model, Block 2 recorded the random forest model, and Block 3 recorded the gradient boosting model. Each block included the previous block hash, linking the records together in sequence. This created a tamper-evident chain of model development history.
To test tamper detection, the audit chain was copied and intentionally modified in several ways. The tests included changing one performance metric, changing a model name, changing a dataset hash, and changing a previous block hash. After each modification, the block hash was recalculated and compared with the saved hash. A mismatch indicated that the audit record had been altered.
Feature importance analysis was added using the random forest and gradient boosting models. Feature importance values were calculated for each clinical variable, averaged across the two models, and saved as a results file. A feature importance chart was also created to visualize which variables contributed most strongly to prediction.
Version 3 expanded the project by adding a neural network model using TensorFlow/Keras. The neural network was included as a deep learning baseline to test whether a simple multilayer perceptron could improve prediction performance compared with the Version 2 traditional machine learning models. The same cleaned dataset, same binary target variable, and same train-test split were used. Because neural networks are sensitive to feature scale, the feature variables were standardized before model training.
The Version 3 neural network used 13 input features, a first dense hidden layer with 16 units and ReLU activation, a second dense hidden layer with 8 units and ReLU activation, and an output layer with 1 unit and sigmoid activation for binary classification. The model used the Adam optimizer, binary cross-entropy loss, a batch size of 16, and early stopping based on validation loss. The model had 369 trainable parameters. It was trained for up to 100 epochs, but early stopping limited training to 27 epochs and restored the best weights.
Version 3 also improved the reproducibility and programming structure of the project. Reusable Python scripts were added to the source folder, including files for data processing, model training, evaluation, audit trail construction, tamper detection, and feature importance analysis. A requirements file was also added to document the core Python packages needed to reproduce the workflow, including pandas, NumPy, scikit-learn, matplotlib, and TensorFlow.
Finally, Version 3 upgraded the audit trail by adding the neural network as a fourth audit block. The Version 3 audit chain included Block 1 for logistic regression, Block 2 for random forest, Block 3 for gradient boosting, and Block 4 for the neural network / multilayer perceptron. The neural network audit block recorded additional deep learning-specific information, including architecture, number of layers, activation functions, optimizer, learning rate, epochs planned, epochs trained, batch size, loss function, and early stopping settings.

Results

Version 1 of the project successfully trained a logistic regression model and generated an initial blockchain-inspired audit record. The logistic regression model achieved an accuracy of 83.3%, precision of 84.6%, recall of 78.6%, F1 score of 81.5%, and ROC-AUC of 94.9%.
Version 2 compared logistic regression, random forest, and gradient boosting models. Logistic regression achieved an accuracy of 83.3%, precision of 84.6%, recall of 78.6%, F1 score of 81.5%, and ROC-AUC of 94.9%. Random forest achieved an accuracy of 85.0%, precision of 88.0%, recall of 78.6%, F1 score of 83.0%, and ROC-AUC of 94.1%. Gradient boosting achieved an accuracy of 76.7%, precision of 76.9%, recall of 71.4%, F1 score of 74.1%, and ROC-AUC of 88.3%.
Overall, in Version 2, random forest produced the highest accuracy and F1 score, while logistic regression produced the highest ROC-AUC. Gradient boosting performed lower than the other two models in this version of the project. These results suggest that model comparison is important because different algorithms may perform better depending on the metric being prioritized.
Version 3 added a neural network / multilayer perceptron model. The neural network achieved an accuracy of 85.0%, precision of 88.0%, recall of 78.6%, F1 score of 83.0%, and ROC-AUC of 94.9%. These results were competitive with the traditional machine learning models. The neural network matched the random forest model in accuracy and precision, produced a similar F1 score, and achieved a ROC-AUC close to the logistic regression model.
The Version 3 comparison showed that the neural network did not clearly outperform the traditional machine learning models, but it performed at a similar level. Logistic regression remained the strongest model by ROC-AUC, random forest remained one of the strongest models by accuracy and F1 score, and the neural network performed competitively across the main evaluation metrics. This suggests that deep learning can be added to the workflow successfully, but that a neural network may not provide a major advantage on a small structured clinical dataset.
The training results also showed signs of possible overfitting. During training, the neural network’s training accuracy increased to approximately 87.8%, while validation accuracy peaked around 77.1% and later remained closer to 72.9%. Training loss continued to decrease while validation loss began to increase after the model had already reached its best validation performance. This pattern suggests that the model was learning the training data more strongly than the validation data. Early stopping was therefore useful because it helped reduce the risk of continuing to train after validation performance stopped improving.
The Version 2 audit chain successfully created three linked audit blocks. The first block recorded the logistic regression model and used a previous block hash of 0. The second block recorded the random forest model and used the first block’s current hash as its previous block hash. The third block recorded the gradient boosting model and used the second block’s current hash as its previous block hash. This confirmed that the audit records were linked together into a sequential chain.
Version 3 expanded the audit chain to four blocks by adding the neural network / multilayer perceptron as Block 4. The fourth block used the gradient boosting block’s current hash as its previous block hash, linking the deep learning model to the prior model history. The neural network block also recorded deep learning-specific information, including architecture, number of layers, activation functions, optimizer, learning rate, epochs planned, epochs trained, batch size, loss function, and early stopping settings. This created a more complete audit record for the deep learning model than would be possible from performance metrics alone.
The tamper-detection tests also worked as expected. The original audit chain was verified as valid. When a performance metric was changed, the audit chain became invalid. When a model name was changed, the audit chain became invalid. When the dataset hash was changed, the audit chain became invalid. When a previous block hash was changed, the audit chain became invalid. These results demonstrate that the audit trail was able to detect changes to model records and chain structure.
Feature importance analysis showed that the most influential variables included thalassemia-related information, chest pain type, number of major vessels, ST depression, age, cholesterol, and maximum heart rate. These results provide an interpretability layer by showing which variables contributed most strongly to the random forest and gradient boosting models.

Discussion

The results suggest that a blockchain-inspired audit trail can strengthen machine learning and deep learning model governance by making the development process more transparent, traceable, and reproducible. Version 1 demonstrated that a single model run could be recorded with a tamper-evident audit record. Version 2 improved the project by adding model comparison, a multi-block audit chain, tamper-detection testing, and feature importance analysis. Version 3 further strengthened the project by adding a neural network model, reusable Python scripts, reproducibility files, and a deep learning audit block.
The neural network was added for two main reasons. First, it allowed the project to include a deep learning baseline and evaluate whether a multilayer perceptron could improve heart disease prediction performance. Second, it allowed the audit trail to be expanded beyond traditional machine learning models by recording deep learning-specific training details. This is important because neural networks often involve more complex architecture and training settings than traditional models. In health AI governance, it is not enough to report that a neural network was trained; the model architecture, training settings, and evaluation results also need to be documented.
The Version 3 results show that the neural network performed competitively, but did not clearly outperform the traditional models. The neural network achieved 85.0% accuracy, 88.0% precision, 78.6% recall, 83.0% F1 score, and 94.9% ROC-AUC. These results were close to the best traditional machine learning results. However, the neural network did not create a clear performance improvement over logistic regression or random forest. This is an important finding because deep learning is not automatically superior in every biomedical prediction task.
One likely reason the neural network did not clearly outperform the traditional models is the small size and tabular structure of the dataset. The cleaned dataset contained fewer than 300 observations, which limits the amount of information available for a neural network to learn. Deep learning models often perform best when there are large datasets, complex input structures, or high-dimensional data such as images, signals, text, or large-scale electronic health records. In contrast, this project used a small structured clinical dataset with 13 input features. For this type of dataset, traditional machine learning models can remain highly competitive.
The training history also suggests possible overfitting. The neural network’s training accuracy continued to improve while validation performance stopped improving and validation loss increased after the best validation point. This pattern indicates that the model may have begun fitting the training data more closely than the validation data. In a health AI context, this matters because a model that performs well on training data but generalizes poorly may be unreliable when applied to new patient data. Early stopping helped reduce this risk, but the overfitting pattern still reinforces the need for careful validation and cautious interpretation.
The traditional models were not necessarily better in every metric, but they remained highly competitive and easier to interpret. Logistic regression achieved the strongest ROC-AUC, and random forest matched the neural network’s accuracy and F1 score. This suggests that, for this dataset, traditional machine learning models may be more practical than a neural network because they can provide strong performance with less complexity. The neural network still adds value to the project because it demonstrates deep learning implementation and shows how deep learning model details can be included in an audit trail.
Interpretability and auditability are especially important in health AI. A model used in a health-related workflow should not be treated as a black box without documentation. Researchers and stakeholders need to understand which variables influenced predictions, how the model was trained, what evaluation metrics were produced, and whether the model record has changed over time. Feature importance analysis helps address interpretability by showing which variables were most influential for the tree-based models. The audit trail helps address auditability by recording dataset hashes, model versions, hyperparameters, performance metrics, and linked block hashes.
The audit chain remains the central contribution of the project because it shows how model history can be tracked across multiple model versions. Instead of simply reporting final model performance, the audit chain records how the workflow changes over time. This is useful for health AI research because it supports accountability and makes it easier to identify which dataset, features, model settings, and metrics were associated with each model run. Version 3 strengthens this contribution by showing that the audit chain can include both traditional machine learning models and deep learning models.
The tamper-detection results demonstrate the value of hash-based auditability. When model records were modified, the recalculated hash no longer matched the saved hash. This shows that the audit trail can detect changes to stored records. Although this project does not implement a full blockchain network, the prototype demonstrates how blockchain-inspired design principles can be applied to health AI model governance.
Feature importance analysis adds another important layer to the project. In health-related prediction workflows, model interpretability matters because researchers and stakeholders need to understand which variables influence predictions. The identification of variables such as chest pain type, thalassemia-related information, number of major vessels, ST depression, age, cholesterol, and maximum heart rate makes the model outputs more explainable and helps connect the project to clinical reasoning.
Overall, Version 3 shows that the project has moved beyond a basic machine learning notebook. It now includes traditional machine learning, deep learning, model comparison, reusable Python code, reproducibility files, audit trail construction, tamper detection, and interpretability analysis. This makes the project a stronger biomedical informatics and health AI governance prototype.

Limitations

This project has several limitations. First, the dataset is relatively small, with fewer than 300 cleaned observations used for modeling. This limits the generalizability of the results and makes the project better suited as a prototype than as a clinically deployable system. Second, the project uses a public dataset rather than real-time clinical data or electronic health record data. Third, the models have not been clinically validated and should not be used for diagnosis, treatment decisions, or direct medical recommendations.
A specific limitation of Version 3 is that the neural network was trained on a small structured clinical dataset. Although the neural network performed competitively, the dataset may not be large enough to fully demonstrate the advantages of deep learning. The model also showed signs of possible overfitting, with training performance continuing to improve while validation performance stopped improving. This means the neural network results should be interpreted cautiously.
Another limitation is that the neural network architecture was intentionally simple. The model used a basic multilayer perceptron with two hidden layers. More advanced deep learning architectures, hyperparameter tuning, regularization methods, dropout, cross-validation, or larger datasets could produce different results. However, the purpose of this version was to create a clear deep learning baseline and connect it to the audit trail, not to maximize model performance.
Another limitation is that the audit trail is blockchain-inspired rather than deployed on a full blockchain network. The project uses hashing and linked audit blocks to create tamper-evident records, but it does not include decentralized consensus, distributed storage, smart contracts, or real-world blockchain infrastructure. This design is appropriate for an early-stage prototype, but future versions could explore whether more advanced blockchain or distributed ledger designs would provide additional benefits.
The feature importance analysis also has limitations. Feature importance values can vary by model type, dataset split, preprocessing choices, and sample size. The results should therefore be interpreted as a way to improve transparency within this project, not as definitive clinical evidence about heart disease risk factors. In addition, the neural network model does not currently include a deep learning-specific interpretability method such as SHAP, LIME, permutation importance, or integrated gradients.

Conclusion

This project demonstrates how machine learning, deep learning, biomedical data science, and blockchain-inspired auditability can be combined to support more transparent and reproducible health AI workflows. Version 1 established a baseline logistic regression model and created an initial audit record. Version 2 strengthened the project by comparing multiple traditional machine learning models, creating a multi-block audit chain, testing tamper detection, and adding feature importance analysis. Version 3 expanded the project further by adding a TensorFlow/Keras neural network, comparing it against traditional models, organizing reusable Python scripts, adding reproducibility files, and extending the audit trail to include a deep learning model block.
The neural network performed competitively with the traditional models, but it did not clearly outperform them. This finding is important because it shows that deep learning should be evaluated carefully rather than assumed to be superior. For small structured clinical datasets, traditional machine learning models may remain highly competitive and may offer advantages in simplicity, interpretability, and reproducibility.
The project is not intended for clinical diagnosis or direct medical recommendation. Instead, it serves as a research-style prototype showing how predictive modeling and auditability can be integrated to improve model governance in health AI development. Future versions can expand the project by incorporating additional datasets, testing fairness and bias, improving neural network regularization, adding deep learning interpretability methods, improving tamper-detection reporting, and exploring more complete blockchain or distributed ledger implementations.
